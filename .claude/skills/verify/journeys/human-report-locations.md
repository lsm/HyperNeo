# Human reports and private completion evidence

Use the isolated metadata wrapper and resource guard in SKILL.md with
`human-report-locations.ts`. The helper owns a random-port daemon, fresh HOME and
hidden data directory, and a refusing GitHub stub. No model or real key is used.

It creates a coding todo with assigned completion evidence. A second todo that
tries to use the human report path as its completion proof must be refused by
neoEvidenceRefusal. The report itself is saved in the synthetic user's
HyperNeo/Travel directory and recorded through the actual Neo todo-edit door.

The real completion runner starts with a missing proof, observes it after it is
written, and completes the todo. Before the fix, the public card read repeats
that hidden path in evidence and status. After the fix, status is Done and the
internal evidence sentence is absent, while the raw proof, check and report
remain intact. The actual file reader refuses the hidden proof and opens the
human report. The delivered runtime-location brief names the report folder and
keeps completion/runtime output private.

Build web for the current head and add `--browser /absolute/fresh/control-dir` to
the helper for the visual journey. Use its browser.json loopback proof-entry URL.
Open the completed Prepare the human report row. Require the human report text
and report.md card, no result.md card or hidden completion sentence. Open the
report card. If All still overlays the preview, close that dialog before reading
the preview panel and record that extra action. Observe Travel report and A report
for the human. Save screenshots
and browser.json with passed:true under the supplied evidence directory, then
create doneFile. Close the owned tab. The helper stops its servers, and the
wrapper saves evidence and immediately removes the synthetic data.

PR1 separately hides doneWhen on start cards. This journey checks the completed
card and report flow without depending on that unmerged branch. Prompt tests
retain the short-root budget and the existing non-coding folder rules. No iOS
changes or physical phone verification are included.
