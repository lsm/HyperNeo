# Front execution

Build web for the checkout and run `neo-front-execution.ts` through `proof-run.sh`
with pinned Bun and the checkout head. The helper uses a fresh HOME and database,
a scripted SDK query, and an ephemeral loopback PCM speech server. No provider
credentials or real model turn are involved.

Drive the authenticated operation door with the switch off, then select a front
model and enable it in the synthetic database. The independent front processor
must publish chat, a status answer backed by one fresh gateway lookup, and a brief
action deferral. Every input must still have its original coordinator delivery.
A repeated input job must preserve one front publication and one speech delivery.

Enable audio listening, send a live-voice input, and require say/audio/end events
plus accepted playing/played receipts. Read the four saved replies through the
human publication projection. Verify no input owner changed, disable the synthetic
switch and clean up. Retain observed.json and the wrapper status.

This proves daemon text and PCM delivery with a scripted model. Provider latency,
model judgment, browser rendering, microphone routing and phone playback are left
to the human's enabled test. The shipped switch stays default-off.
