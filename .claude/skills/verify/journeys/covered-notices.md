# Card-covered repeat notices

Use the metadata-only setup from SKILL.md with Bun 1.4.2:

```sh
bash .claude/skills/verify/proof-run.sh "$EVIDENCE" .claude/skills/verify/covered-notices.ts
```

The helper owns a random-port daemon, disposable HOME/DB, a refusing GitHub stub
and an authenticated local RPC socket. The production worker-question writer
creates the positive card, its source and answer route. Real work.status reads
terminal SDK records, and driver refresh delivers the first blocker report to
Neo's mailbox. Its repeat stays quiet only while the same worker's card remains
open for the current needs-human action. The stored question title must equal
the current blocked reason. Closed/replaced cards, a changed blocker, additional
evidence and accepted work.send receipts retain the next report. A generic card
or start card on the same todo also retains delivery.

The same refresh admits stalled reminders. Public message.status confirms their
consumed or failed producer receipts. Every reminder case reaches two inputs,
including a consumed reminder whose todo has an open card. A todo reference
alone cannot prove that answering the card resolves retry/escalation work.
Save covered-notices.json and proof.log, including the wrapper exit status.
Both service and daemon close in finally. This proves durable mailbox admission
and receipt handling without a model turn, live daemon, browser or external service.

Focused tests pair the environment-blocker/start-card case with ordinary delivery.
They also retain daily check-only reminders, failed report admission, missing or
mismatched worker sources, and uncovered stalled-ask reminders. Existing
stalled-ask-wake and per-todo-stall-reminders journeys cover reminder contracts.
