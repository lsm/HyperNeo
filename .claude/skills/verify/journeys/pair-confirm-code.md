# Enter the phone's confirmation code on the trusted computer

Follow SKILL.md's isolated metadata proof setup. Build the current web tree before
running the helper. Select installed Playwright through NODE_PATH and its browser
executable through VERIFY_BROWSER; neither credentials nor provider keys are
inherited. Use the pinned Bun runtime and resource guard.

```sh
bash .claude/skills/verify/proof-run.sh "$EVIDENCE" .claude/skills/verify/pair-confirm-code.ts
```

The actual daemon owns an ephemeral listener and disposable database. A legacy
lastGroup approval is schema-refused without consuming the request. A synthetic
trusted browser waits for the phone, then Settings accepts a normalized code and
the bound requester redeems once. The Neo drawer rejects a wrong code permanently;
a subsequent correct approval cannot recover the denied request. The pending RPC
exposes only twoWay/phoneConfirmed, not groups or the expected confirmation code.

Retain the five light/dark, desktop/narrow browser screenshots and
pair-confirm-code.json. Screenshots are captured before entering generated codes;
no pairing code, cookie or credential is written into evidence. Browser console
errors fail the proof. Native phone rendering is not tested by this journey.

Both trusted approval screens keep Allow disabled for eight digits and preserve
the pending request. Normalized alphabet letters still enable approval. A
well-shaped submitted mismatch still permanently denies the request once.
The readiness correction changes no markup or visual styling.
