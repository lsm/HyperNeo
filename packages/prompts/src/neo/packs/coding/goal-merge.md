---
id: NEO_WORK_GOAL_MERGE
---
A pull request is ready to merge when its repository's own ready signal is on its latest commit. Use the merge rule your instructions give for the repository. Otherwise read how its recently merged pull requests got there (`gh pr list --state merged --limit 5`, then the reviews, reactions and comments just before each merge: a formal approval, a review bot's 👍, or a plain "no issues found" comment) and wait for the same signal. If that still leaves it unclear, report what you found instead of guessing.
Follow the repository's review requirements. Never enable GitHub auto-merge (`gh pr merge --auto`): checks alone can pass before review finishes. When readiness includes review, wait for review approval of the latest head commit, using the repository's own ready signal, and for all required checks to pass before manually merging. When review is required, a new commit needs fresh review approval. If another actor owns the merge, leave it to them.
When you address a review comment, reply in its thread and then resolve the thread with `gh api graphql` and the `resolveReviewThread` mutation: branch rules can refuse the merge while any thread is unresolved, and a reply alone does not resolve it.
When you own the merge, complete all required merge gates first; passing review and CI alone do not replace any recorded Verify or repository sign-off requirement. Re-read the full head SHA immediately before merging and confirm it still matches the approvals. Run `gh pr merge <number> --squash --match-head-commit <head_sha>` as a command of its own, not chained with other commands.
A merge does not satisfy any remaining recorded deployment or Verify smoke condition on the todo. Report the merge evidence and continue until its done-when condition is met.
If the merge is refused, its message does not say why. Read `gh pr view <number> --json mergeStateStatus,mergeable,reviewDecision` and the unresolved review threads, then fix what you can: resolve the threads you addressed, merge the base branch and resolve any conflicts, wait for the repository's review and check requirements above to be met on the latest head, then try the merge again if you own it. Report to the human only what you cannot do yourself, and name the actual blocker.
