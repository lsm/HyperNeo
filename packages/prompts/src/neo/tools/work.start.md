id: work.start
---
Start new work in a place returned by work.find: a session, thread or task titled title, opened with message. Workers are long-lived sessions: title is named for the matter, never a task title. Put the task in message. excludeRefs prevents the named workers receiving a reused start, including PR authors and earlier stage actors. For Neo, offer a todo first to the most recently used free worker of its ask with the same adapter and folder. A new todo reuses a daemon-started worker only after confirmed compaction; otherwise it starts a fresh worker. The same todo can continue on its existing worker. Reuse returns reused true and that worker ref. Prepared workers can be reused only when their preparation matches; createFolder starts new work. Explicit model or effort can reuse only after the adapter resolves and confirms matching identity. Agent starts require a todo on an accepted human request. adapter picks the harness: an adapter whose capabilities include start (see work.adapters); a place group lists adapters that only found work there. A place with a daemon starts the work on that daemon. A remote route forwards explicit model and effort when that daemon's work.adapters lists the adapter as configurable, and its adapter confirms them there; otherwise it returns unsupported_model or unsupported_effort without starting work. Only Neo or the user can change work on another daemon; other agents get unsupported. For non-coding work, omit place and pass todoId to use the one visible user folder across projects: ~/HyperNeo by default, or exactly the instance workspace path. A different place needs an exact path the user named in chat, even inside the workspace; never invent folders under home. Other new human-named folders keep the existing home-only, non-hidden and existing-parent creation rules. Coding keeps the repository place returned by work.find. model picks the model of a new HyperNeo session or Codex thread; settings.model.get lists HyperNeo id, name and provider. HyperNeo resolves a unique case-insensitive display name, with exact IDs taking precedence; ambiguous names reject with matching IDs. A shared exact ID keeps catalog precedence; use a unique display name to choose a particular provider offer. Codex resolves catalog aliases and refuses unsupported models. Every Neo start on a local adapter must name provider, model and effort, or it is refused identity_required (the detail lists what is missing); provider may be omitted only where the adapter fixes it (codex-desktop openai, claude-desktop anthropic, cursor, antigravity, copilot github-copilot) and must agree with it. Claude desktop and Cursor cannot apply or read back the request: they start as asked and the request is recorded, effective value unknown. Effort is local HyperNeo (off/low/medium/high/extra high/max/ultra or thinking-level IDs) and Codex: it resolves against the selected model catalog and confirms the applied effort before sending the first turn. Antigravity CLI accepts model and effort on new sessions. Use an advertised model ID or an unambiguous display name. The selected model determines the available effort values. Pick effort by task: trivial lookups low, ordinary changes medium, hard debugging or design high, rare deepest work max. For Neo, an eligible idle worker of the same ask may be reused; the requested model and effort reuse a worker only when they match its recorded identity; otherwise a fresh worker starts. Human starts always create new work. For Codex and Copilot, place names the project; execution reports the worker’s actual folder. Repositories without a first commit start in the project folder. Returns the started or reused work with its ref, link and, for HyperNeo or Codex, the model it runs on plus confirmed effort when available, or ok false with a reason such as invalid_place, claude_cli_login_expired, unsupported or unreachable. Antigravity CLI reports the confirmed model and effort when available.
For Copilot (adapter ID copilot-cli), copilotClient defaults to auto, which preserves normal worker reuse, including existing CLI workers. When opening a new session, auto prefers Desktop and falls back to CLI only before sending. Use desktop or cli to require that client on the selected machine. Explicit client choices start a new session. A remote server must advertise copilotClients before it can honor an explicit selection, including its model and effort. The result's copilotClient tells the user where the session actually opened.
