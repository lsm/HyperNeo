Deliver a message in this conversation. Use a new requestId per message and reuse it only when retrying that send. session is the worker session this message is about; omit it otherwise. When the latest listening fact is yes, include optional spoken: one or two natural lines consistent with the text, at most 500 characters. Publication is saved first, speech is delivered to the current listener, then clients are notified of the text. No listener silently drops spoken; speech is not stored in publication history. Retries never replay speech. The receipt reports listening and spokenDelivered. If a fresh receipt says listening yes but you supplied no spoken, follow its guidance to call neo.speech.say once; never re-publish the text. text is the message about one matter; publish unrelated matters as separate messages. Use Markdown: a short bold title line that states the conclusion or the decision the human must make, then a few bullets or a small table, with the key choice in bold; no walls of text. Write at most 60 words; details hold only supporting material. Before any number or internal name, say in a few plain words what it is. Give times in the zone of the local time on the human's messages unless they asked for another. Separately, the server refuses text over 400 characters. Details shorter than the text fold into it when the result stays within that limit. Pass deliverable: true with no details for a translation, drafted email or message, or text to paste: the whole of text is then the complete copyable deliverable, exempt from the reply limit and running to at most 64000 characters, and a revision resends the full text instead of describing edits. Optional replyTo lists the received human message ids this publication answers; when omitted the publication answers no human input, exactly like replyTo: []. Only the ids you list are recorded as answered. An unknown, foreign, queued or non-human reply id rejects the publication without saving; correct the list and retry the same requestId. When a reply is about one session the human may want to open, pass session: its exact session id rather than promising a link in text. Unknown session ids reject the publication without saving; correct the id and retry the same requestId. session_lookup_failed means the lookup is unavailable: retry the same requestId and session id. If session is omitted, the daemon fills it only for an unambiguous recorded sender of the current inputs. Only project links are accepted; an unknown project id rejects the entire publication without saving. Correct the link and retry with the same requestId. Unavailable artifact references reject the publication; correct them and retry the same requestId. For a working document, put its absolute path on the owning daemon in the text and say in one sentence what it is. Attach a worker handoff using its publicReference; never expose private work or evidence paths. Preview only files on this daemon. Remote files return owner_unavailable; identify their owner rather than re-publishing their paths as local. Artifacts may contain saved attachments, fixed-head Git references, or verified local Markdown/HTML handoff publicReference values. An existing card-reply handoff must be retained when updating artifacts.
