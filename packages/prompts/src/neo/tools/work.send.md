---
id: work.send
---
Message existing work by the ref from work.find, work.start or work.status. Agents need a todo on an accepted human request. Neo may use notice:true only to reply to a session that messaged it. Only Neo or the human can send across daemons.

- Ordinary local Neo input is stored durably with inputId and waits while the worker runs or is queued. A question ending the turn permits delivery. Explicit steer is immediate.
- Use auto for adapter defaults. HyperNeo sessions and Space agents do not support explicit steer; use auto for them. Explicit modes require the capabilities in work.adapters and refuse without sending if unsupported. Copilot auto and queue enqueue; steer sends one best-effort immediate input that may start a later turn.
- For Codex, use steer for immediate feedback and queue for the next turn. While Codex Desktop runs, auto and steer route through Desktop ownership discovery without resuming an app-server writer. Explicit queue returns busy if Desktop owns the thread. With Desktop closed, auto queues for the next idle turn and steer uses the app-server. Native queue resumes saved, unloaded threads only and does not start a turn. If Codex steering is unavailable, expect not_delivered with a reason and no queue fallback. Never retry or queue an uncertain steer.
- Claude UUIDs registered with Desktop use its confirmed send path even when stopped. Plain CLI sends refuse unknown receiver permission modes without sending. For claude_cli_login_expired, tell the human to run `claude auth login`; retrying cannot help.
- An idle Claude session can look archived on the phone after Remote Control drops: ask the human for approval, then send it a short no-op message and turn Remote Control back on. Skip this for desktop-only use and leave actually archived sessions alone.

A receipt (executionId, inputId) belongs to the requested ref and daemon. Use it with work.status before retrying uncertain sends and to verify their replies. delivered:false normally indicates acceptance without consumption; a receipt or queuedSubmissionId identifies the submission. delivered:true requires matching input evidence for a queued submission. If unconfirmed:true, only the transport write is known and peer acceptance is unknown. A held receipt needs receive-side approval; do not resend on hold or expiry. Neither acceptance nor delivery proves completion or result origin. Claude Desktop remains ui-unconfirmed unless supported live acknowledgment exists; delivered, confirmedAt, links and Remote Control do not prove rendering or reading. ok:false means failure or uncertainty. Only notSent:true proves no input was accepted; otherwise check work.status before retrying a failed send. not_open means archived or ended; other refusals include not_found, not_delivered, unsupported and unreachable.
