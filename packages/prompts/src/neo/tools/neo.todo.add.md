id: neo.todo.add
---
Add a titled todo. For a human's direct request that the root does not send to neo.ask.propose, pass input: the daemon opens its ask or finds the open one, and the todo starts without a card; pass a topic of up to 12 display cells when this opens a new ask. For follow-up work pass askId of an open ask you own; a settled ask refuses with ask_settled, adds nothing and names the next step. Use the root's human-input routing and add every step with after: [] for parallel work, or the exact prerequisite IDs. Missing after is refused. A chain waits on the previous step. For multi-PR work, use one PR per todo with a merge check, chain the todos with after, and pin each opened PR with neo.todo.edit addUrls.

Pass check {pack,kind,params}. The daemon generates doneWhen; do not supply it. Use an installed pack's supported check, such as core.human_confirmed {questionId} or core.evidence {path: absolute path} or {url: link}. Coding uses pr_merged, pr_approved, issue_closed, deployed {repo,sha: full commit}, or core.evidence {url} for a review or comment link. Checks can refuse or return bookkeeping records. Prefer the existing live todo if a PR is already tracked; duplicate claims are recorded without blocking.

- Give every step that needs execution its instruction and target: {verb:start,adapter,place?,model?,effort?} or {verb:send,ref}. For a send that may need a prepared replacement, include this todo's preparationParameters and sandbox so the checkout is not guessed. Omit both instruction and target for a check-only wait; the daemon checks it and gives you the next step if the check is unmet 24 hours after prerequisite completion.
- For a start that requires a specific model or thinking effort, set target.model or target.effort. The instruction text never selects either. After dispatch, use neo.todo.read to verify the recorded settings before reporting that the requested worker started.
- Bind work already underway with {verb:bind,ref}, no instruction, and satisfied prerequisites (after: [] if parallel). It records doing without sending. Coding send and bind refuse unknown or mismatched worker remotes.
- Workers are long-lived sessions. Name them for the project and a number, never for a task. New local workers default to '<engine> <project> <n>'; use target.name only for another name that follows this rule. named records the engine, session, repository or folder the human named. For a named session require an exact work.find {session} ref.
- A step that must use this computer lists its apps' bundle ids in desktopApps; only that todo gets them. Each app must be on the ask's approved proposal card or named by the human message in input; otherwise propose the work with desktopApps. Follow the computer-use pack guidance, and leave named.desktopControl out.

A runnable todo starts once its prerequisites pass and a slot is free. Never start todos yourself. There is no start flag or Start card. Set priority from human urgency: urgent, high, normal (default), low. Set producesFollowUp:true for work that yields later steps. On completion, add those steps with after:[its id]; the daemon wakes you and done settlement waits for a successor, which can be unstarted.
For Copilot (adapter ID copilot-cli), set target.copilotClient to desktop or cli when the human requires that client. Otherwise use auto or omit it. After dispatch, work.status reports the actual copilotClient alongside the session reference.
