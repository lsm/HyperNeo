# Disk work off the daemon main thread

**Design for human review; no implementation authorized yet.** #7843 stays first. Merge this document only after Neo relays human design approval AND exact-head bot approval/green CI; a PR-sweep nudge is not human approval. Goal: no SQLite or synchronous filesystem/lock/checkpoint work on the main thread, including startup and shutdown. Moving SQL does not by itself make slow queries fast.

## Boundary and transactions

Use one persistent **writer worker plus one read-only reader worker** initially; add readers only if measured queue delay justifies their memory. Main owns RPC, authorization and subscriptions; workers own SQLite connections, statements, repository execution and DB-related files. Async `postMessage({id, epoch, operation, args})` → Promise reply `{id, epoch, result, committedScopes, timings}`; typed internal commands, not a new agent SQL endpoint. Reuse `storage/sqlite-compat.ts:18` on Bun/Deno, existing permission checks, scoped-query isolation and statement cache. No synchronous proxy, `Atomics.wait`, connection/statement/closure transfer or main-thread fallback on worker failure.

Each command is one serial worker job. A multi-statement write runs its **entire existing synchronous transaction** there, including nested savepoints, constraint checks, triggers and return-value reads; it never awaits network/main callbacks while holding a transaction. Closures such as `submit: () => T` become named business commands with data arguments, not separate remote BEGIN/step/COMMIT calls. Move the existing pure decisions with the handler; keep external effects after commit. Ordinary multi-query read commands use one short read snapshot when required by today's semantics; no snapshot spans a socket wait.

Writer replies only after commit. Read-your-writes uses a read included in that command or an awaited write followed by a **new** reader snapshot; a writer fence must run before a dependent read if callers dispatch concurrently. During coexistence, legacy writes must also finish before dependent reads; a worker-local sequence cannot fence unported/external writers. Return changed tables/scopes with the commit and emit once on main before resolving the write; rollback emits nothing. Worker-originated writes must not depend on today's synchronous reactive proxy doing post-write DB lookups. Async live-query evaluations need generation/disposal tokens so stale replies cannot overwrite newer snapshots.

Serialization is real main-thread CPU: measure argument cloning, queue wait, SQL/lock time, worker assembly, reply clone and main encode/diff separately. Project metadata before full bodies; paginate/stream large bodies using transferable byte buffers and acknowledgments so replies cannot accumulate. Never truncate stored text/tool results. One oversized body still has to be delivered completely; measure that case rather than declaring the 1 s goal met from small replies.

## Proof and failure boundaries

For **every implementation unit**, commit a failing/contract test first; leave a repeatable verify-skill helper and test both runtimes in CI. Compare baseline/fixed isolated daemons through the real affected RPC/subscription (not a worker-only mock), synthetic production-shaped rows (`replacement_metadata_normalized=1`, production derivation), cold/warm pages and competing writer/readers. Record **max** loop lag (<1 s), hot SQL/transaction time (<250 ms), unaffected health and affected RPC latency (target <250 ms), queue delay, cloning bytes/time, RSS, WAL growth and correctness/full-body hashes. A blocked writer may leave its own affected RPC slow even while health stays responsive: report that failure, not a full pass. Inject worker death before/after commit, cancellation, stale subscription replies and held locks. No GUI test, live copy, key/auth file or port 8399. This docs-only PR verifies references and rendered Markdown; it proves no runtime improvement.

After each deploy read live logs only, grouped by build/PID: worker SQL metrics must retain the existing normalized fingerprints and include request/queue/commit timings; correlate with main `event_loop.lag_activity` and RPC spans. Missing coverage is inconclusive. A health request independent of DB must remain available while workers wait. Do not restart or write the live daemon to collect evidence.

Workers add caches/RSS and can starve behind one long command: start with one reader, bounded in-flight bytes and paged results, then tune measured concurrency. Keep WAL/foreign-key/durability settings, short snapshots and explicit worker checkpoints; existing FTS/CLI/other connections can still contend, so worker ownership is not a global SQLite mutex. Preserve the PID lock across worker replacement. On shutdown reject new work, drain accepted jobs, settle commit replies, close readers then checkpoint/close writer off-thread and release the lock. Worker death rolls back open transactions; a write that committed before its reply was lost has **unknown outcome**—do not replay it without a durable receipt/idempotency key. No claim of exactly-once notification: restart/resubscription must reconcile committed state. Migrations/DDL run exclusively before reader-ready, never twice in a worker constructor. Tests must await persistence/initial snapshots, use file-backed synthetic WAL for cross-worker tests (`:memory:` is not shared), inject worker factories, and terminate every worker; retain existing ordering, rollback, pin and no-trimming assertions.
