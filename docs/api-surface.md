# API surface snapshot

Run `bun run api:surface` after changing an operation's input/result schema or a
server-to-client event method or payload schema, then commit `api-surface.json` with the change.
`bun run check:api-surface` compares generated bytes without rewriting the file;
it is part of `bun run check` and CI. Run `bun run test:api-surface` for the tooling tests.

The exporter collects the complete built-in operation catalog from an isolated
throwaway daemon and checks it against the declared operation names. It uses
Zod's JSON Schema input/output modes, sorts operation/event names and object keys,
and records no generation timestamp or machine data. No model, credentials or
external HTTP/GitHub access is required. Temporary homes, databases and listeners
are removed after collection.

Client event names come from daemon MessageHub event calls, typed client gateway
calls, direct `createEventMessage` calls and bridge mappings. Literal constants and finite template expressions are
resolved; an unresolved direct event name fails generation instead of silently
omitting it. This list excludes internal event-bus topics and legacy RPC requests.

`eventSchemas` records received payload contracts for the pinned phone inventory's
literal event subscriptions. The daemon owns the Zod definitions; producer types
reuse them without adding production parsing or changing delivered data. JSON
Schema uses Zod input mode so additional session/settings metadata remains allowed.
Live-query rows are explicitly open, query-specific records, not complete row models.
Regeneration refuses a phone-used event without a schema or a schema without an
advertised event. Run `bun run test:api-events` for contract and diff tests.

Event payload changes use result compatibility rules in `api:diff`. The first
schema for a previously untracked payload is marked coverage-only and excluded
from phone compatibility counts: it does not prove the historical payload was
compatible. Historical collection loads schemas only when that source ref owns
them; it never applies today's schemas to an old release.

JSON Schema cannot express every Zod construct. Such nodes carry an explicit
`x-zod-unrepresentable` annotation; transforms also carry a SHA-256 fingerprint of
their function source, making transform edits visible without publishing runtime
values. These nodes are permissive JSON Schema, not complete output validators.
Representable siblings retain their schemas. Arrays preserve schema order.

The committed snapshot uses the exporter's canonical JSON formatting; Biome skips
this generated file, while the drift check enforces its exact bytes. This snapshot
records the contract for review; it does not itself declare compatibility or
introduce a generated client.
