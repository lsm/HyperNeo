# Neo route classifier eval

Compares route classifiers for Neo (#5710) on one question: given the topics, the recent turns
and a new message, where does the message go — a topic id, `main`, or `inbox`?

Every candidate sees the same input, built by `context.ts` in the #5708 layout: topics (title,
summary, latest exchange, WAITING line), recent turns newest first within 3,000 characters, then
the new message. Decision models receive it as a Jev/Kev `/v1/systemone` Choice question, so
hosted Jev, Cloudflare Clef, Kev or llama.cpp can be swapped by URL.

## Cases

- `cases/synthetic.json` — generated by `bun scripts/neo-route-eval/synthetic.ts` from five
  made-up topics. Kinds: follow-up, second-last topic, "yes" to a WAITING question, "yes" with
  two waiting, one-offs, new subjects, thanks, long dictated asks, mixed Chinese/English.
- `cases/real.json` — built from a **copy** of a daemon DB with
  `bun scripts/neo-route-eval/build-real.ts --db <copy>` and hand labels in `real-labels.json`.
  Both are gitignored because they hold personal conversation.

## Running

```bash
# current classifier path (Agent SDK), as deployed or lean (no auto-memory, empty cwd, short system prompt)
bun scripts/neo-route-eval/run.ts --backend sdk --provider anthropic|glm|codex \
  --prompt message-only|context --shape deployed|lean --out scripts/neo-route-eval/results/<machine>-<name>.jsonl

# any /v1/systemone server: kev.serve, llama-server with a Kev GGUF, or adapters/encoder_server.py
bun scripts/neo-route-eval/run.ts --backend systemone --url http://host:port --out results/<machine>-<name>.jsonl

bun scripts/neo-route-eval/report.ts
```

`--provider codex` runs `gpt-5.6-luna` through HyperNeo's Codex bridge and forces
`reasoning.effort = none` on the upstream request; every SDK run passes `thinking: disabled`.
`adapters/encoder_server.py` puts GLiNER2.5-Decide and Laya behind `/v1/systemone`.
Results are gitignored.
